## Overview

This repository contains a fully restored, corrected, and extended version of a
deliberately corrupted clinical image-classification pipeline. Starting from a
volatile set of recovered scripts, the codebase has been audited line-by-line,
every runtime error, silent logical flaw, and production-readiness violation
has been fixed and logged, and the pipeline has been extended in two directions
beyond the original baseline restoration:

1. **Baseline restoration** — three classification architectures (AlexNet,
   VGG16, ResNet18), config-driven and compatible with all four target
   datasets (`cells`, `chest`, `lesions`, `orgs`).
2. **Green Initiative** — a fourth, purpose-built lightweight architecture
   (`GreenNet`) achieving comparable accuracy to the three baselines at a small
   fraction of their parameter count, training time, inference latency, and
   memory footprint.
3. **Data-scarcity transfer learning** — a frozen-feature transfer strategy
   adapting knowledge from the larger `orgs` dataset to a new, much smaller
   `organs` dataset, benchmarked against training from scratch.

Full technical detail on each of the above is documented in
[`REPORT.md`](./REPORT.md) (benchmark results and analysis) and
[`AUDIT_LOG.md`](./AUDIT_LOG.md) (itemized bug/fix history with commit hashes).

## Data setup

The dataset itself is not committed to the repository (`data/` and `data.zip`
are both excluded via `.gitignore`, since the raw tensors are too large for
version control).

1. Download the dataset archive from:
   `https://cloud.fiw.fhws.de/s/LpYa2dCW85kwdNn`
2. Extract it into a `data/` folder at the **repository root**, as a sibling
   of `Code/` (not inside it).
3. Confirm the following files exist directly under `data/`:
   `cells.pt`, `chest.pt`, `lesions.pt`, `orgs.pt`, `organs.pt`.
4. `config.json`'s `DATA_PATH` is set to `../data` by default — this is
   correct as long as you run the scripts from inside `Code/` (see below), so
   the path resolves up one level to the repository-root `data/` folder. If
   your local layout differs, adjust the path in `config.json` accordingly.

## Running the pipeline

All commands below are run from **inside the `Code/` directory**:

```bash
cd Code
```

### Full benchmark sweep (Parts 1, 2, and 3 — recommended)

```bash
python runner.py
```

This will, in order:

1. Train and evaluate **all four models** (`AlexNet`, `VGG16`, `ResNet18`,
   `GreenNet`) on **all four datasets** (`cells`, `chest`, `lesions`, `orgs`) —
   16 runs total — appending results to `results.csv` (inside `Code/`) after
   each run.
2. Automatically continue into the Phase 3 transfer-learning study on the
   `organs` dataset, training each architecture both from scratch and via
   frozen-feature transfer from its corresponding `orgs`-pretrained checkpoint,
   appending results to `results_transfer.csv` (inside `Code/`).

Checkpoints for every run are saved under `Code/checkpoints/` and reused
automatically for the Phase 3 transfer step.

### Single training run

To train a single model/dataset combination without running the full sweep,
edit the top-level `"DATA"` and `"MODEL"` keys in `config.json`, then run:

```bash
python train.py
```

This executes exactly one training + evaluation run using whichever
dataset/model/hyperparameters are currently set in `config.json`, and prints a
`[RESULT]` summary line to stdout without writing to `results.csv`.

## Configuration

Every hyperparameter, path, and model/dataset selection is controlled from a
single file: `Code/config.json`. No source file requires manual editing to
change datasets, models, or hyperparameters.

| Key | Purpose |
|---|---|
| `DATA` / `MODEL` | Dataset/model used by a single `python train.py` run |
| `DATA_PATH` | Path to the data directory, relative to wherever the scripts are run from |
| `BATCH_SIZE`, `LEARNING_RATE`, `EPOCHS`, `DROP_RATE`, `ACTIVATION`, `SEED` | Core training hyperparameters (Parts 1 & 2) |
| `MODELS` | List of models `runner.py` sweeps over |
| `DATASETS` | Per-dataset `CHANNELS`/`NUM_CLASSES` metadata |
| `TRANSFER_DATASET` / `TRANSFER_DATASET_CFG` | Which dataset and channel/class config Phase 3 targets |
| `TRANSFER_LEARNING_RATE`, `TRANSFER_DROP_RATE`, `TRANSFER_BATCH_SIZE`, `TRANSFER_EPOCHS` | Phase-3-specific hyperparameters, independent of the Part 1/2 sweep settings |

## Output artifacts

| File | Produced by | Contents |
|---|---|---|
| `Code/results.csv` | `runner.py` | Test loss/accuracy/precision/recall/F1, val loss, train time, inference latency, peak memory (train & inference), checkpoint path, per dataset–model run |
| `Code/results_transfer.csv` | `runner.py` (Phase 3) | Same core metrics for each model, scratch vs. transfer, on the `organs` dataset |
| `Code/checkpoints/*.pth` | `train.py` / `runner.py` | Best-validation-loss model weights per run, reused for Phase 3 transfer |

## Results summary

Full benchmark tables, architectural recommendations, the Green Initiative
efficiency analysis, and the organs data-scarcity post-mortem are in
[`REPORT.md`](./REPORT.md). Headline results:

- **15 of 16** baseline/GreenNet runs clear their required accuracy threshold
  (`cells` ≥ 90%, `chest` ≥ 87%, `lesions` ≥ 67%, `orgs` ≥ 83%).
- **GreenNet** matches baseline accuracy within 1.6–3.5 percentage points on
  average while using **409–907× fewer parameters** and training **2–20×
  faster**.
- **Transfer learning** on the scarce `organs` dataset improves test accuracy
  by **+2 to +42 percentage points** over training from scratch, and every
  transfer result clears the required 40% floor.

For the full incident log of every bug found and fixed during the restoration,
including root cause and commit hash, see [`AUDIT_LOG.md`](./AUDIT_LOG.md).

## Reproducibility

All training runs are seeded (`SEED = 33` by default, configurable in
`config.json`) across Python's `random`, NumPy, and PyTorch (CPU and CUDA)
RNGs, with `torch.backends.cudnn.deterministic = True`. Re-running the full
sweep with an unmodified `config.json` reproduces the results in `results.csv`
and `results_transfer.csv` exactly.
